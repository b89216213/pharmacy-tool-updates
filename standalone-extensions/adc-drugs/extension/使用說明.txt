ADC 特殊藥品批次取歸藥 v1.2.0：自動更新與後台管理

首次升級
1. 等所有取歸藥、盤點作業完成。
2. 解壓縮新版，把裡面所有檔案覆蓋至原本 Chrome 載入的工具資料夾；請勿先移除擴充功能。保留相同資料夾與擴充功能 ID，原有本機紀錄與設定才會接續。
3. chrome://extensions 重新載入此工具，並重新整理 Portal。首次新增管理及更新網址權限，請接受 Chrome 顯示的權限提示。
4. 開啟「電腦登記／工具更新」。從 https://pharmacy-device-console.cx760.chatgpt.site/ 取得 4 位一次性碼，輸入電腦名稱與碼。若同一台已有貼片或另一工具，後台請選既有電腦再產生新碼。每個工具需一組新碼，登記後共用同一筆電腦資料。
5. 於工具更新指定目前載入的工具資料夾（含 manifest.json），不是報表資料夾。工具會驗證這確實是載入位置。

後續更新
開啟工具會自動檢查；開著時每 6 小時檢查。找到新版會顯示更新提示；在設定頁按「更新並重新開啟」套用。更新程式寫回已授權資料夾並重新載入，不需要 GitHub 帳號；Chrome 可能再次詢問寫入授權。更新後請重新整理 Portal。
有取歸藥或盤點作業時不能更新，也不會在作業中自動重新整理 Portal。驗證失敗不寫入；寫入中斷會嘗試還原，未完成時下次可選「還原原版檔案」。請保持更新頁開啟。

管理政策
開啟工具時每分鐘回報電腦名稱、工具版本與管理狀態；後台不接收病人資料、藥帳、報表、取歸藥紀錄或數量。工具各自接受最低版本或停用設定；已執行的批次會繼續收集結果，禁止下一批。最後驗證後可離線 24 小時，已接收的限制仍有效。
本版為 Chrome 獨立工具；iPad 腳本與整合工作台未變更。

保留功能
ADC 特殊藥品批次取藥 v1.1.5

從舊版更新
1. 確認目前沒有取藥正在執行，再關閉工具視窗。
2. 解壓縮新版，將檔案覆蓋到原本固定位置的 adc-helper 資料夾。
3. 開啟 chrome://extensions，在原本的擴充元件按「重新載入」。
4. 重新整理 Portal「特殊藥品管理」頁面，再開啟工具。
沿用原資料夾與擴充元件，不要移除後重裝，以保留執行紀錄與資料夾設定。
舊版已完成的項目仍保留，不會因更新而重新取藥；舊紀錄仍顯示當時的 ADC 備註。

安裝
1. 將 ZIP 完整解壓縮，將 adc-helper 資料夾放在固定位置。
2. Chrome 網址列輸入 chrome://extensions，開啟右上角「開發人員模式」。
3. 點「載入未封裝項目」，選擇內含 manifest.json 的 adc-helper 資料夾。
4. 在擴充功能選單中釘選「ADC 特殊藥品批次取藥」。
5. 點工具圖示後開啟一個獨立視窗；再次點圖示會回到同一視窗。

首次設定與每日使用
1. 在同一個 Chrome 使用者設定檔登入院內 Portal，開啟「特殊藥品管理」。
2. 點擴充元件圖示。在工具內選擇「報表根目錄」。
   例如：D:\ADC報表\20261012\14PW_補藥報表_20261012-134547.xlsx
   應選擇 D:\ADC報表，而不是 20261012。
3. 工具記住根目錄；下次開啟自動讀取今日日期子資料夾。
   Chrome 若要求重新授權，按「允許讀取」。權限僅為讀取，不修改原報表。
4. 確認檔案清單與取藥勾選項目，按「開始批次取藥」。
   報表尚未放齊時，放好後按「重新讀取」。

固定規則
- 今日以台灣日期計算，子資料夾名稱為 YYYYMMDD。
- 只處理該子資料夾直屬的 *_補藥報表_YYYYMMDD-134xxx.xlsx。
- 080xxx、其他時間、其他日期、Excel 暫存檔與分揀總表不作為取藥資料。
- 若同裝置有多份符合條件的檔案，需在檔案清單選一份；不會相加。
- 八碼為品項比對依據；保留八碼內的空白，例如 MO 5GA45。
- 讀取「分揀量」。同一裝置、同一藥品的不同藥格加總。
- 床號去掉前導 0，例如 03E2 → 3E2。
- 05W4-1、05W4-2 分別登錄為 5W4-1、5W4-2。
- 3E2、3W2 的 MOD4IA33（Modipanol）預設略過，仍可自行勾選。
- 作業藥局固定西址住院藥局（T02）。初次進入頁面時先選藥局，等待取藥按鈕顯示才繼續。
- 領藥號填 ADC；帳號、病歷號、備註留白。
- 取藥前盤點沿用 Portal 當下帶出的數量，直接下一步，不要求實體盤點。
  報表的「目前數量」是 ADC 藥格存量，不會拿來填藥局的盤點量。
- 同一藥品依病房逐筆登錄，不會把不同病房合成一筆帳。

執行結果與中斷
- 每筆完成後先保存成功紀錄，再等待至少 0.2 秒，並確認 Portal 回到主選單、載入與對話框結束後，才接續下一筆。
- 選藥、下一步、填寫與送出等中間步驟改為約 0.05 秒的就緒確認，取消原本額外的 0.4 秒載入後停頓；若頁面仍在載入則繼續等待。每筆完成後間隔 0.2 秒，並同步檢查主選單是否穩定；若已就緒，不會再額外疊加等待時間。
- 若已登錄成功但主選單未恢復，停止後續操作，該筆仍保留為已完成，不會重送。
- 請保持工具與 Portal 頁面開啟。執行期間不要在該 Portal 頁操作其他功能。
- 已完成：Portal 回覆成功，並核對藥碼、病房、ADC、數量、單位與結存變化。
- 未完成：尚未送出，處理顯示原因後可繼續。
- 待核對：可能已送出，但無法完整確認。工具不會自動重送。
  請按「回 Portal」，由「報表 → 使用明細」核對，再按該列「核對結果」。
  只有確認沒有登錄時，才能選「已確認未登錄，允許重試」。
- 按「停止」後不再開始下一筆；若當筆已送出，會先等待結果。
- 關閉或重新載入工具後，已完成與待核對紀錄仍會保留。
- 同日同病房同藥碼的已完成項目不會因重讀報表而重新取藥。
- 報表數量與既有已完成紀錄不同時，不會自動取差額或重送，請回 Portal 核對。
- 此版以每日一批 134 報表為範圍；同日追加領用請另外處理。
- 結果可匯出 CSV。

測試工具：批次歸藥
- 入口在頁面底部，小字「測試工具」，預設收合。
- 選擇原取藥日期，勾選測試時確實要歸還的紀錄，按「歸還勾選項目」。
- 清單只列本工具已確認成功（包含人工核對成功）的取藥紀錄。預設不勾選。
- 歸藥使用原紀錄的病房、八碼、數量與單位；不依重新匯入的報表推算。
- 作業藥局固定西址住院藥局，進入 Portal「歸藥」，領藥號填 ADC，備註留白。
- 歸藥前沿用 Portal 當下結存，逐筆確認歸回數量與結存增加後才標記完成。
- 已歸藥不會重複歸還；結果不明時停止後續操作，請按「核對歸藥」核對使用明細。
- 若已在 Portal 手動歸藥，勿再勾選同一筆執行歸藥。
- 已歸藥的今日項目可勾選後按「允許重新測試取藥」，再回上方開始取藥。
- 每次取藥與歸藥均保留紀錄，匯出結果包含歷次測試。原本的取藥登錄不會被刪除。
- 歸藥恢復的是這次測試扣除的數量；若期間有其他人取藥／歸藥，總結存仍反映那些操作。
- 只有此 Chrome 擴充元件已保留的紀錄可用；未確認成功的項目需先核對，不能直接歸藥。
- 不必重新選擇報表資料夾也能使用已保存的歸藥紀錄，但仍須連接 Portal。

資料處理
Excel 在本機解析；工具不會將報表傳到外部服務。
登錄操作透過現有、已登入的 Portal 頁面原生控制項執行。
不保存登入憑證、密碼或病人資料。
請固定使用同一個 Chrome 使用者設定檔與擴充元件安裝位置，以保留資料夾授權與執行紀錄。
若移除擴充元件或清除其資料，本機紀錄會消失。

驗證範圍
已依提供的報表與錄製頁面製作，並以離線測試檢查報表篩選及取藥流程。
開發環境未連上院內 Portal，無法在此直接完成真實院內取藥驗證。
若 Portal 結構與錄製內容不同，工具會顯示未能確認的位置並停止後續項目。
