# 藥車標籤列印 v2.17.0 正式版驗證（2026-11-07）

以 GitHub main 的正式版 2.10.0 為基礎，原始 55 個檔案與取得的正式來源逐檔相符；參考貼片回收 1.6.0。來源提交：`0db469c29b840be72f1be7731638f49a66cfd3f0`。

## 功能與相容

- 早上／下午病房組合各自選擇，卡片直接顯示病房；台北時間 12 點切換預選組合，開啟及切換時自動擷取。
- 依實際交車日曆取得前兩次交車日期；只用指定的較早比對日，不用今天或更舊的替代紀錄。缺資料時列印在床病人。
- 相同標籤不重印、不占格，後續標籤前補。空床僅由比對日床位與完整擷取的在床名單推得；不再使用預設床位表。
- 列印與儲存兩顆直接按鈕；選儲存即保存，取消原生列印也保留。相同已存工作再次只列印不改紀錄。
- 重新開啟後，全部所選病房今天有已存紀錄，且完整原始在床名單的校驗值一致，才恢復「已儲存本次紀錄」。新增、出院、轉床、部分擷取、缺任一病房或紀錄被改皆不顯示。
- 名單證據與實際貼紙狀態分開保存；手動排除、選擇不印空白貼紙時，仍保留原貼紙狀態，不會把未印內容當成已印。
- 舊 2.10.0 日期／病房／床號／病歷號紀錄按原有身分比對續用，保留在原儲存鍵。未臆造姓名、生日或完整名單證明；真正列印才轉為完整標籤狀態。矛盾的同床舊紀錄不省印。
- 既有 TXT 可續讀與同步；保留轉床後同病歷號的不同床位。外部修改只撤銷受影響病房的完整已存證據。
- 設定自動儲存、版面微調、06PE／08PE 預設兩張、其他一張、例外上限五張；今日可出院預設照常印。

## Portal、管理與更新

Portal Connection、engine、bridge、core、operation-guard 採貼片回收 1.6.0；engine 僅調整檔名匯入路徑。使用原頁功能與查詢按鈕切換病房，病歷號仍透過 Portal 列印標籤的原解析器取得。

沿用 cart 工具身分、登記儲存鍵、安裝 ID、憑證、工具限定的 device policy scope 與更新資料庫。登記／心跳由背景共用管理，避免頁面和背景覆寫彼此資料。資料夾沿用、SHA-256、更新前備份、manifest 最後寫入、失敗還原與重新開啟對齊最新共用機制。

原 2.10.0 更新器直接驗證並模擬安裝本版 75 檔完整套件；保留必要的舊 manager 入口，權限、存取範圍、識別與 CSP 不擴大。更新後重新整理 Portal。更新只發布程式碼，未包含瀏覽器設定檔、真實病人紀錄或憑證。

## 範圍限制

沒有院內真實 Portal、Windows 原生資料夾選擇器或實體印表機環境，因此未宣稱實機驗收。回院內首次使用需核對實際名單與印表機定位。本次沒有修改院內資料或登記真實電腦，也沒有內建測試病人的正式功能。
