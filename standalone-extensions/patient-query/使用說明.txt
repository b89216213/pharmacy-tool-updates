病人快速選擇 1.6.0

本版更新（1.6.0）
- 新增「工具更新」：開啟時及持續開啟每 6 小時檢查 GitHub 新版；有新版時待作業
  空閒再提示。按「更新並重新開啟」才會套用，處理病人或批次結清時不能更新。
- 新增電腦登記及既有後台管理：輸入電腦名稱與管理員提供的 4 位數字登記碼。
  後台可查看版本、最後回報時間，分工具設定最低版本、停用／恢復與生效時間。
- 同一台電腦可以登記多個工具，各工具的管理政策獨立。工具每分鐘回報一次，
  只傳電腦識別、工具版本與管理狀態，不傳病人、搜尋或結清資料。
- 管理限制生效時，完成目前病人的核對後停止後續病人及病房，不中斷已送出的操作。
- 更新採檔案完整性檢查；失敗嘗試還原。更新後不會自動續跑任何結清工作。
- v1.5.3 或更早版本首次需手動更新至本版，再完成電腦登記及指定更新資料夾。

電腦登記與管理
1. 管理員開啟 https://pharmacy-device-console.cx760.chatgpt.site，以自己的帳號登入。
2. 按「新增電腦」，建立一次性 4 位數登記碼。如果該電腦已登記其他工具，選擇
   既有電腦即可共用同一裝置識別；不需修改既有工具設定。
3. 開啟病人快速選擇，輸入電腦名稱與登記碼，按「登記並開始使用」。前面的 0
   也必須輸入。登記碼 10 分鐘有效、僅用一次；新碼會取代前一組未使用的碼。
4. 後台「電腦與版本」可篩選「病人快速選擇」；個別列的「設定」只調整該工具。
   「使用政策」先選病人快速選擇，再設定全部電腦的最低版本或暫停使用。
5. 停用或版本限制收到後先停止新作業，等目前一位完成才鎖定；更新及重新連線
   入口仍可使用。後台收到套用回報後才顯示「已生效」。
6. 工具關閉時不回報；最後驗證後可離線使用 24 小時。已收到的停用、最低版本
   或預定生效限制仍會執行；超過期限需重新連線。首次登記必須連線。

工具內更新（完成首次手動更新後）
1. 點上方「工具更新」→「指定資料夾」，選目前瀏覽器實際載入的 extension 資料夾，
   授權讀寫。不是 ZIP 所在目錄，也不是另一份備份的 extension 資料夾。
2. 工具會記住位置並自動檢查新版；也可按「檢查新版」。無需登入 GitHub 或填 Token。
3. 有新版時先完成目前工作、關閉其他選人視窗，再按「更新並重新開啟」。
   會先驗證版本與完整性、保存回復用檔案，寫入完成後重新載入擴充元件。
4. 更新會重新開啟對應工具視窗；病人名單需重新取得，先前勾選與結清排程不會續跑。
5. 若失敗，畫面會說明原因；需要時按「還原原版檔案」，或依下方步驟手動覆蓋更新。
   更新資料夾必須有寫入權限，院內網路需能存取 raw.githubusercontent.com 與後台網址。

跨病房批次結清
1. 按左欄最下面「跨病房批次結清」，病房按鈕會改為勾選框，院區分類維持不變。
2. 勾選要處理的病房；可以切換院區繼續勾選，上方會列出全部已選病房。
   病房不預先勾選，依你勾選的順序執行。可點病房代號旁的 × 個別移除。
3. 選擇處理項目，預設兩項都勾選：
   - 在床病人：今日出院的病人（包含備註中的可出院日期）。
   - 已清床：所有「藥帳未結清」的病人（辨識狀態或備註欄）。
4. 按「開始結清」。工具逐房查詢在床、勾選今日出院、逐一結清，再查已清床、
   勾選藥帳未結清、逐一結清；未勾選的處理項目不會執行。
   使用各病房完整的一般名單，不套用原有搜尋或 Smart Care 篩選。
5. 畫面會同步切換病房與來源，在病人清單上方的同一進度區顯示正在查詢／勾選／
   結清，並顯示病房進度、目前床號與姓名、病人進度及累計結果。
   原系統也會實際依序查詢、選人、結清、返回名單。
   如要同時觀看原系統，可將兩個視窗並排；請保留原分頁並避免執行中手動操作。
6. 要中止時按「停止後續處理」：目前這位完成後停止，不會開始其他病人或病房。
   查詢期間按停止，會等本次查詢返回，不再開始結清；已送出的操作不會撤銷。
7. 完成或停止後顯示總結果。按「查看處理紀錄」可展開各病房的在床／已清床統計。
   警示、未執行、待確認者會直接列在下面，保留床號、姓名與原因；不能視為成功結清。
8. 完成後仍可按「開始結清」，重新查核同一批病房；帳務異動後可再次處理。
   也可按「返回單病房選擇」，繼續原本的單筆或多位病人結清。

跨病房流程如何處理例外
- 空病房、沒有符合病人：略過，繼續下一項或下一個病房。
- 個別病人的警示：留下原因，繼續其他病人。同一輪不重送同一住院帳號，
  即使途中從在床轉到已清床，也會顯示「本次已處理」並略過重複帳號。
- 沒有原系統選取入口的病人：列出「無選取入口」，不當成成功結清。
- 每位送出前重新查核身分、最新出院日期或未結清註記；條件改變會略過。
- 登入／連線失效、返回名單失敗或名單無法確認：停止後續處理。
- 原系統有分頁：目前無法確認取得全部名單，停止並說明，不把一頁當成全部。
- 執行中跨過台灣午夜：停止；重新開始後才使用新的今日出院日期。
- 名單、勾選與結果只在工具視窗記憶體，關閉後不會自動續跑。

使用
1. 登入院內系統，開啟實際的「查詢處理」頁面。
2. 從該分頁按擴充元件圖示，工具另開選人視窗。
3. 點常用病房，或依兒醫、西址、健大、東址選病房；病房代號直接讀自原系統。
4. 病房旁的 ☆／★ 可加入或移除常用病房。
5. 點選病房一律重新查詢「在床病人」；需要已清床時再按「已清床」。
   重新整理會保留目前名單來源，更新完成前暫停選取舊名單。
6. 點病人列，會在原院內分頁開啟病人；選人視窗保留原病房、搜尋與捲動位置。
7. 病人頁右下角「← 選擇其他病人」可回到選人視窗，也可直接切回工具視窗。

結清
- 按病人列右側「結清」，會重新查詢並核對該次住院帳號、姓名、床位，進入病人
  頁後再核對病歷號，才執行原系統結清與其「確定執行藥品結清？」確認。
- 已出院或完成出院結帳仍可點結清；原病人頁提供可用結清按鈕時才執行。
  原系統沒有病人選取入口時，工具無法代為進入，該列按鈕維持停用。
- 執行期間停用其他病人操作，完成後返回選人畫面；搜尋和位置保留。
- 每次操作結束後，按鈕一律恢復為可點的「結清」；每次都重新查詢原系統。
  原系統當下仍已結清時只回報現況；若帳務異動變成未結清，會再執行結清。
- 兩種需先退藥的畫面內警示會立即回報；其他警示與非預期確認也會停止該筆。
- 有警示、未執行或結果不明時，按鈕同樣恢復為「結清」，可再次點選重新查核。
- 未能確認結果會在該病人列顯示原因；不會自動重送，使用者可再次按「結清」
  啟動新一輪查詢與核對。原系統仍已結清時只回報現況。

批次結清
可在任何病人清單按「全選今日出院」，依出院日期一次勾選目前顯示的符合者。
按鈕為一般白底，不使用特別醒目的顏色；右側人數只計可勾選病人。
不可選取的病人仍可顯示今日出院標記，但不會納入快捷勾選。獨立日期欄空白時，
會讀取備註中明確的「月／日可出院」等註記；其他事項的日期不當成出院日。
名單未載入的病房／其他分頁不會自動加入。
1. 在床號左側勾選要處理的病人；勾選只用於批次，不會開啟病人。
2. 可用「全選目前清單」勾選目前顯示且原系統可選取的病人，包含搜尋結果。
   不會納入其他未顯示的病人或未讀取分頁。切換病房、在床／已清床、Smart Care、
   搜尋條件或重新整理會清除勾選；上方會顯示已選人數。
3. 按「批次結清（人數）」，依顯示順序逐一執行；處理期間暫停切換名單。
   每位重新查詢並核對，所有結果留在各自病人列；有警示的單筆不會自動重試。
4. 上方顯示當前床號、姓名、已處理數，以及結清／原已結清／警示／未執行／
   待確認統計。結果只在工具視窗記憶體中保存，不會寫入磁碟或背景恢復執行。
5. 按「停止後續處理」，會讓目前這位完成核對與處理，再停止尚未開始的病人；
   不會撤銷已送出的結清。結果列出已處理與尚未處理人數。
6. 原系統登入失效、分頁關閉／切換網站或無法返回名單時，停止後續處理。
   原分頁關閉會清除工具內病人資料與勾選。
7. 批次完成或停止後，每列恢復「結清」，勾選保留；可調整勾選後再次手動執行。
   「取消勾選」清空選擇；列內 × 收起個別結果，上方 × 收起批次統計。
   請保留工具與院內分頁開啟直到完成；執行期間不要在原系統切換病人。

搜尋
- 同一個搜尋框，不需要先切換輸入類型；姓名不在查詢範圍。
- 01：按 Enter 查目前病房的 01 病室。
- 01-01、12-A：查目前病房指定的病室與病床。12-A 與病房代號 12A 不同。
- 12PE-01-01：直接透過原系統查 12PE 的 01 病室、01 床，不限已載入病房。
- 12PW：按 Enter 查詢 12PW 的在床病人；亦可點出現的病房按鈕。
- 完整數字病歷號、住院帳號、身分證號：送出原系統病人查詢，跨病房顯示結果。
  身分證號欄也可輸入原系統接受的新／舊式居留證號格式。
- 輸入中會先篩選已載入名單；按 Enter 或「搜尋」才會向原系統查詢。
  查詢完成顯示「搜尋結果」，並顯示每位病人的完整病房／床號。
- 點選病人，或以 ↑ ↓ 選定後按 Enter 開啟；未選定時 Enter 一律送出查詢，
  即使篩選結果只有一位也不自動開啟。
- 床位查詢保留在床／已清床來源，兩個頁籤可切換同一床位的來源。
  病人識別資料查詢的結果範圍依原系統回傳，不套用目前病房或 Smart Care。
- / 將焦點移到搜尋框；Esc 清除搜尋或關閉完整資訊。
- 原名單未提供病歷號時顯示「尚未取得」；開啟病人並確認身分後才補上。
  以病歷號查詢時，開啟與結清還會核對病人頁的病歷號是否符合查詢條件。

資料更新
- 每次切換病房、名單來源或 Smart Care 均取得原系統更新後名單，並顯示更新時間。
- Smart Care 若自行更新名單，直接讀取該結果；若只是查詢條件，才按查詢。
  原系統若回傳其他病房的 Smart Care 病人，會保留並顯示完整病房代號。
- 在床、已清床與 Smart Care 條件分開暫存，不會把另一種來源當成目前名單。
- 開啟病人前核對住院帳號、姓名與床位；舊名單依其來源重新查詢。
- 若病人床位或住院身分已變動，會提示重新整理，不會照舊列的位置點選。
- 每次查詢／勾選動作不會因讀取中斷而重送；確認回應及名單穩定後才顯示。
- 「重新整理」保留搜尋文字，重新取得目前病房或同一組搜尋條件的結果。
- 原系統未提供選取按鈕的已清床病人仍可閱讀資料，病人列不提供開啟操作。

- 病人名單、已取得的病歷號、搜尋文字與最近選人只存在工具視窗記憶體。
- 關閉視窗、來源分頁關閉或登入失效後，需重新讀取資料。
- 不上傳病人、查詢或結清內容；沒有 GPT API 或勘查錄製，安裝包沒有真實病人資料。
- 本機另保存電腦登記憑證、管理政策及更新資料夾授權／還原檔。後台僅接收電腦識別、
  工具版本及管理狀態；GitHub 連線僅下載公開更新檔。
- 操作期間原院內分頁暫存操作代碼、確認／送出旗標與警示；不含工具傳入的姓名、
  帳號或病歷號。完成即清除，最長 60 秒失效；來源警示本身可能含原系統文字。
- 病人內頁與其他檢驗視窗維持原系統；本版負責病房及病人導航。
- 一般搜尋範圍會標示已載入病房；跨病房批次結清只遍歷本次明確勾選的病房。
- 若原表格使用分頁，會提示目前只讀取一頁；此版不會自動翻頁。

無法擷取時
- 確認工具是從實際的「查詢處理」分頁開啟，不是 Portal 的入口選單。
- 原系統若出現登入畫面或警示，先在原分頁處理，再按「重新連接」。
- 錯誤訊息旁可按「匯出相容性資訊」，提供產生的 JSON 與顯示的錯誤訊息。
  此檔只含控制項結構與操作階段，不含姓名、病歷號、帳號、欄位值、網址或 HTML。
- 若「已清床」不可點選，表示尚未辨識到可用的原系統按鈕，請重新連接。
