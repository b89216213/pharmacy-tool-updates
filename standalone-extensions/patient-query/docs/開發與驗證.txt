作業區內覆寫按鈕／勾選／hover／focus 共用色彩變數為作業區藍色，包含深色模式。
移除 processSettlement 逐人 scrollIntoView；只在 startWardBatch 開始時回頂端。
執行期間停用 document scroll anchoring，避免重繪或名單高度變更導致自動捲動，
不封鎖使用者自行捲動。既有跨病房檢查加入捲動紀錄：從頁面中段開始，三病房
切換與逐人處理只會有最初一次回頂端，沒有跟隨病人列的捲動，完成後仍在頂端。

根因：舊 billingMarkup 只在未確認時加入橘色強調，確認後回傳原字串，因此
備註仍顯示藥帳未結清。原檢查只確認顏色與待結清狀態已移除，未檢查可見文字。

沿用 settlementHint 的時間判斷：success / already 且確認時間不早於名單，
才將狀態與備註中由 billingUnsettledText 辨識的片段顯示為「藥帳已結清」。
支援空白、全形冒號與同欄重複片段；所有原文字仍 escapeHTML。其他備註、日期、
出院狀態保留。顯示文字有本次確認與原查詢文字的 title；完整資訊另外列出本次
已確認結清，並把原備註標成查詢時原文。原快取、原院內資料與結清引擎未修改。
警示／未執行／不明／處理中不轉成成功；新查詢會覆蓋較舊的確認狀態。

新增兩組真正 app / engine / bridge 的合成整合檢查，檢查可見文字而非只看顏色：
成功、already、不重送、原字串與快取不變、重複及空白片段、HTML escaping、
收起訊息後仍顯示正確、較新查詢恢復未結清、Smart Care／帳號查詢、批次成功與
警示／未知混合結果及未結清全選人數。合計 96 項離線檢查通過，尚未院內實測。

1.5.0 跨病房批次結清
來源：GitHub main 9de906495840c99e7162043f49c74d6080634485 的 patient-query 1.4.2。

序列工作函式。UI 顯示實際病房、來源、勾選與當前病人，查詢及勾選階段各留
500 ms 顯示時間；原生動作仍由既有 engine / bridge 逐一點擊，無平行送出。

新增可選的 settlementCriteria 只供本輪自動流程使用：preparePatient fresh query
後再次確認今日出院日期（含備註）或明確藥帳未結清文字，變更者列 skipped。
既有手動單筆與多位結清不附帶此篩選限制；使用者仍可重複點選結清。
住院帳號在每輪最多嘗試一次，包含警示或未知結果；再次手動開始會重新建立集合。
選取入口缺失列入未執行，結果按病房／來源彙總，警示保留姓名、床號與原因。

停止標記在每個 await 後檢查；若病人已開始則完成目前這位，其餘不再執行。
跨來源／跨病房維持同一停止旗標，原有病人批次停止鈕也會停止整輪。
名單查詢失敗、條件被替換、分頁、來源失效、日期跨日或無法返回名單都停止。
來源關閉讓 request 失效並清除病人、勾選及跨病房歷史；延遲回覆不得重建資料。
偏好儲存仍只有 pinned、lastWard、campus，不新增病房排程或患者資料持久化。

1.4.2 辨識備註的原生可出院日期
根因：原生在床查詢把「10/08可出院」放在未命名的備註欄；bridge 已擷取 note，
但前版今日出院判斷只讀 discharge。先前合成資料主要以獨立日期欄建立情境，
未覆蓋備註為唯一出院日期的實際格式，導致標示與快捷勾選一起漏判。

本次重新讀取使用者先前上傳的 2026-10-07 勘查檔，從五份一般病人表的備註
確認 MM/DD可出院，共 15 筆重複畫面中的備註實例（每份三筆，並非 15 位不同病人）。
只保存彙總檢查結果至 note-capture-check-results.json，不附原始畫面或病人資訊。

新增共用 dischargeInfo：獨立欄可解析為完整日期時優先使用；否則僅匹配備註中
與出院標籤直接相連的日期。支援原生月日、明確標籤前後日期、完整西元／民國日期、
常見分隔及全形字元。月日用當下 Asia/Taipei 年份驗證及比對，並非持久推定年份；
不改寫原始 discharge 或 note，也不改變原已清床按完整出院日期的排序。
相鄰藥品／衛教等非出院日期、已辨識的取消／延期文字、不合法日期或衝突的多個
出院日期不納入。獨立欄與備註衝突時採獨立欄；未試圖理解任意自然語言備註。

isTodayDischarge 保留原有完整日期字串介面，另接受完整病人列；批次快捷改傳病人列。
標記也用 dischargeInfo，並以 title 顯示原獨立日期或「備註：」加上採用的片段。
備註原文仍留在病人列，不新增醒目色彩、不增加院內查詢、不更動原生結清流程。

驗證新增三組解析檢查，既有多來源 UI 流程改用真正的備註格式重現：在床、已清床、
Smart Care、床位／病歷號／住院帳號／身分證搜尋中，原 discharge 空白、note 有
月日可出院時仍正確標記與勾選。覆蓋跨年、台灣午夜、取消、其他事件日期、非法日期、
不同出院日期及原欄優先；批次僅處理選中帳號的流程亦通過。共 81 項離線檢查。
真實備註唯讀驗證：15 筆在指定出院日全數符合、勘查當天全數不符合；未執行原系統
腳本或任何操作。舊 capture-check-results.json 是前版 Smart Care 結構解析的紀錄。

1.4.0 單一搜尋框與原生跨病房查詢
依既有畫面快照確認 QueryInPatientByPersonBox 的 txbChartNo、txbAccountIdse、
txbPersonId 及 btnQuery，並使用實際 QueryInPatientByBedBox 的 txbBedNo
（相容舊 txbBedCode）。姓名搜尋不實作，輸入預覽也不再按姓名篩選。

parseSearch 將輸入分為病房、床位、病歷號、住院帳號、身分證號。保留前置零；
支援全形輸入、大小寫及明確分隔的完整床位。12A 是病房、12-A 是房床；
含空白的 0PI I 與 0PII 可對應同一院內選項。不猜未知病房或無分隔完整床位。
病人查詢先清空其他識別欄位及姓名候選，避免原系統帳號 > 身分證 > 病歷號的
優先序使用舊值。不觸發姓名或病房下拉選單的自動 postback，只按原生查詢一次。
床位查詢填入指定病室／床號；完整病房查詢仍清空這兩個篩選欄位。

查詢後等待本次回應及穩定名單，再核對原欄位、帳號或指定床位，錯誤時不接受。
每列記錄 queryPerson／queryBed／queryMRN 與來源供過期重查、選人及結清使用；
已清床床位重查仍按已清床，不換成在床現住者。病歷號查詢在病人頁再次核對
查詢的病歷號，即使清單本身沒有病歷號欄，也不省略結清前驗證。
Smart Care 在這些原生查詢前切回一般模式，回病房名單則仍依使用者原有設定。

已知上一版會成功勾選後再按一般查詢；原生勾選自行更新名單時，可能覆蓋結果。
